# Шаблоны документов docs/product/

Этот файл читает /prd-project перед черновиком (шаг 4).

## Шаблон docs/product/project.md
```markdown
# <Название проекта>

<Только если есть исходное описание: Исходное описание продукта — docs/brief/<файл>. Подробности фич берём оттуда; если оно расходится с документами в docs/product/, верны документы в docs/product/.>

## Коротко
<2–3 предложения: что это и для кого.>

## Проблема
<Что сейчас плохо у пользователей и как они справляются без программы.>

## Цель
<Какой результат считаем успехом. По возможности — так, чтобы можно было проверить. Если у проекта есть план версий — цель по каждой версии.>

## Пользователи и роли
| Роль | Кто это | Что делает в системе |
|---|---|---|
| … | … | … |

## Основные сценарии
<По одному пункту на сценарий, без деталей. Детали — в описаниях фич.>
1. …

## Ограничения
- Языки интерфейса: …
- Устройства: …
- Где будет работать: …
- Пользователи и объём данных: …
- Безопасность и данные: …
- Стек: задан шаблоном, см. CLAUDE.md.

## Не входит в проект
- …

## Открытые вопросы
- (нет)

### Решим в /prd-features
- (нет)

### Решим в описаниях фич
- (нет)
```

Разделы исходного описания, которым нет места в шаблоне (например, принципы удобства, структура приложения), добавляй отдельными разделами после «Основных сценариев». Конкретные проверяемые правила из них — ещё и в rules.md, с номерами BR.

## Шаблон docs/product/glossary.md
```markdown
# Глоссарий

Термины предметной области. В документах, спеках, интерфейсе и коде используем только их.
«В коде» — имя для кода (по-английски), одно и то же во всех файлах; если у термина есть набор значений — они тоже здесь, например `status`: `todo`, `done`.
<Только если есть план версий: Пометка в начале «Что значит», например «(2.0)», — термин появится в этой версии.>

| Термин | Что значит | В коде |
|---|---|---|
| … | … | … |
```

- Если терминов много — дели их на группы по темам: заголовок `### <Тема>`, под ним та же таблица.
- Возможные значения термина пиши в колонке «В коде», например `status`: `todo`, `done`.
- У терминов будущих версий — пометка версии в начале колонки «Что значит», например «(2.0)».

## Шаблон docs/product/rules.md
```markdown
# Бизнес-правила

Общие правила, которые действуют в нескольких фичах. Правила одной фичи — в её описании.
Номера правил не меняются и не используются повторно.

## BR-01. <Правило коротко>
<Что именно обязательно или запрещено. Пример.>
Действует в: везде
```

Поле «Действует в» на старте обычно «везде»; конкретные фичи (F-xx) туда потом добавляет /prd-feature.
